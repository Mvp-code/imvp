# Components (Cursor)

## Buttons
- Use primary buttons for the key action on each view.
- Use secondary buttons for non-destructive alternatives.
- Best practices: clear action verbs and explicit states (`hover`, `focus`, `disabled`, `loading`).

## Forms
- Use progressive capture with inline validation and actionable error messages.
- Group fields by user task, not by raw data type.
- Best practices: labels are mandatory; placeholders are supportive only.

## Cards
- Use cards to group scannable content and related actions.
- Keep hierarchy stable: title, supporting metadata, then CTA.
- Best practices: avoid overcrowding; emphasize one primary action per card.

## Navigation
- Use top navigation for global context and side navigation for complex application depth.
- Make current location and next actions obvious.
- Best practices: name sections by user goals, not internal org structure.
